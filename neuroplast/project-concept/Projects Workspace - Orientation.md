# Projects Workspace - Orientation
#project-concept
## Purpose
Provide the top-level shell for creating, organizing, opening, archiving, and switching between multiple books and writing projects.

## Current Reality
The repository now includes a local-first manuscript workspace with multi-project switching, a lighter professional shell, sharper shared surface treatment, surface-specific layouts that stack dense content more vertically when that keeps the main canvas calmer and easier to scan, and wrap-safe text handling for longer real project titles and metadata.

## Desired Outcome
The author can manage multiple books and related writing projects from one coherent workspace without losing focus or context.

The current UX direction favors a stable left rail plus a page-specific main workspace instead of treating every surface like the same three-column layout.

## Important Actors or Stakeholders
- Primary author
- Future account-backed single user across devices

## Key Artifacts or Interfaces
- Project list — shows all active and archived projects
- Project dashboard — entrypoint into manuscript, planning, and worldbuilding areas
- Project metadata — title, status, genre, series, tags

## Constraints
- Must support multiple independent projects from v1
- Must be local-first now and sync-ready later
- Must stay optimized for a single author in v1

## Open Questions
- Should projects support nested series/grouping in v1 or shortly after?
- What project-level metadata is mandatory versus optional?
