# 2026-05-05
#changelog

## Summary
- Added a project-details editing workflow so existing projects (including the seeded example project) can be renamed and have metadata updated directly from the shell.
- Introduced a dedicated metadata edit dialog and `ProjectDetailsForm` for title, genre, status, and description updates.
- Added a domain-level `updateProjectDetails` operation and wired it through workspace persistence so updates flow through the same optimistic/debounced IndexedDB save path as other project changes.
- Added guarded primary-book title sync during rename when the primary book still mirrored the previous project title, preserving default naming consistency.
- Added project lifecycle-state support (`active`, `archived`, `trashed`) so archive and trash are first-class project controls.
- Implemented trash-first deletion behavior by moving projects to `trashed` state instead of permanently deleting them.
- Added sidebar toggles to keep archived and trashed projects hidden by default while still making them restorable on demand.
- Added archive/trash/restore controls and active-project fallback behavior so selecting and working contexts remain stable after lifecycle transitions.
- Updated architecture and README artifacts to reflect editable seeded project metadata behavior.
- Verified changes with `npm run typecheck`, `npm run lint`, and `npm run build`.
